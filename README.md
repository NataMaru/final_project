# Прогнозування рекомендації товару за відгуком клієнта (Women's E-Commerce Clothing Reviews)

Фінальний ML-проєкт: бінарна класифікація тексту відгуку клієнта інтернет-магазину одягу з метою передбачити, чи рекомендує клієнт товар. Порівняно 5 моделей - від класичного TF-IDF + Logistic Regression до fine-tuned DistilBERT.


## 1. Аналіз вакансій на ринку та відповідність проєкту тенденціям

Проаналізовано 3 вакансії Data Scientist / ML в retail та e-commerce з фокусом на сегментацію клієнтів.
Усі три вакансії - і глобальний ритейлер (Walmart), і менші компанії - прямо називають **сегментацію клієнтів** ключовою задачею, часто саме на основі текстових/поведінкових даних, що напряму перегукується із задачею цього проєкту (класифікація клієнтських текстів). Спільна вимога у всіх трьох - не лише побудова моделі, а й **вміння перекласти результат у бізнес-рішення** ("translate complex findings into actionable insights", "communication skills", технічне лідерство). Це і визначило акцент цього проєкту: показати не тільки порівняння 5 моделей і fine-tuning DistilBERT, а й чітке обґрунтування бізнес-задачі, рішень з preprocessing та практичних висновків - оскільки саме це однаково цінується і в ML/DS ролях, і в напрямку дата-аналітики з ростом у менеджмент, який я обираю для себе.

## 2. Бізнес-задача та мета

### Проблема

Інтернет-магазини отримують тисячі текстових відгуків щодня. Ручний перегляд кожного - повільний і не масштабується. Компанія дізнається про незадоволення клієнта лише тоді, коли він сам виставить низький рейтинг або публічно поскаржиться - часто вже запізно для утримання клієнта.

### Рішення

Модель, яка за текстом відгуку (без очікування явного рейтингу) автоматично передбачає, чи рекомендує клієнт товар.

### Бізнес-цінність

- **Швидше реагування:** команда підтримки бачить незадоволеного клієнта одразу з тексту, а не постфактум з рейтингу - можна оперативно запропонувати повернення/обмін/компенсацію.
- **Пріоритезація черги відгуків:** замість перегляду всіх відгуків підряд, команда спершу бачить ті, де модель впевнена в незадоволенні.
- **Агрегований сигнал по категоріях:** якщо певна категорія товару (наприклад, конкретний департамент) систематично отримує більше "не рекомендую" - це сигнал для команди закупівель/якості, ще до того як це стане помітно в рейтингах.

**Тип задачі (технічно):** supervised learning, бінарна класифікація.
**Цільова змінна:** `Recommended IND` (1 - рекомендує, 0 - не рекомендує).

## 3. Дані

**Джерело:** [Women's E-Commerce Clothing Reviews, Kaggle](https://www.kaggle.com/datasets/nicapotato/womens-ecommerce-clothing-reviews)

**Розмір:** 23 486 записів (до preprocessing), 10 полів.

**Опис:** реальні (анонімізовані) відгуки клієнтів жіночого одягового інтернет-магазину. Згадки про компанію в тексті замінені на "retailer".

**Поля:**

| Поле | Опис |
|------|------|
| Clothing ID | ідентифікатор товару |
| Age | вік рецензента |
| Title | заголовок відгуку |
| Review Text | текст відгуку |
| Rating | оцінка товару від 1 до 5 |
| Recommended IND | цільова змінна: 1 - рекомендує, 0 - не рекомендує |
| Positive Feedback Count | кількість клієнтів, які вважали відгук корисним |
| Division Name | верхньорівневий підрозділ товару |
| Department Name | департамент товару |
| Class Name | клас товару |

**Preprocessing та обґрунтування рішень:**

| Дія | Чому |
|-----|------|
| Видалено `Rating` | сильна кореляція з ціллю - модель "підглядала" б відповідь замість аналізу тексту (data leakage) |
| Видалено `Title` | забагато пропусків |
| Видалено `Clothing ID` | 878 з 1206 товарів мають ≤5 відгуків - агрегати по товару були б статистично ненадійні |
| Видалено рядки з пропусками в категоріях товару | лише 14 рядків (<0.1% даних) |
| `Age` - створено `Age Group` (4 категорії) | зручніше для моделі та інтерпретації, прибирає вплив поодиноких вікових викидів |
| `Positive Feedback Count` - логарифмовано | сильно скошений розподіл (більшість - 0, є поодинокі викиди 100+) |
| Додано `review_word_count` | довжина відгуку - потенційно інформативна ознака |

## 4. Метрика оцінювання

**Основна метрика: F1-score.**

*Чому F1-score:* клас "рекомендує" значно переважає над "не рекомендує" у даних і саме F1-score враховує баланс між тим, скільки реальних незадоволених клієнтів модель знаходить, і скільки хибних тривог вона створює.

**Допоміжна метрика: ROC-AUC** - показує загальну якість ранжування моделі незалежно від конкретного порогу прийняття рішення.

---

## 5. Підхід до розв'язку та інструменти

| Модель | Опис підходу | Навіщо саме ця модель у порівнянні |
|--------|--------------|--------------------------------------|
| Logistic Regression (baseline) | TF-IDF (1-2 n-грами, 5000 ознак) + Logistic Regression | швидка, інтерпретована точка відліку |
| LightGBM | TF-IDF + табличні ознаки (вік, категорія товару, довжина відгуку) | перевірка, чи додають цінність метадані поза текстом |
| LightGBM + Optuna | ті самі ознаки, гіперпараметри підібрані автоматично (30 trials) | оцінка приросту від тюнінгу без зміни архітектури |
| Neural Network | Embedding-шар + усереднення векторів + Dense-шари | простий нейромережевий підхід без важких обчислень |
| **DistilBERT (фінальна модель)** | fine-tuning попередньо навченої мовної моделі на тексті відгуку | розуміє контекст і порядок слів - критично для заперечень/нюансів |

**Стек:** Python, pandas, scikit-learn, LightGBM, Optuna, TensorFlow/Keras, PyTorch, HuggingFace Transformers, matplotlib/seaborn.

**Розбиття даних:** train / validation / test = 64% / 16% / 20%, стратифіковане за цільовою змінною. Test set використано **лише один раз**, для фінальної оцінки вже обраної моделі - весь вибір моделі та підбір гіперпараметрів відбувався виключно на validation, щоб фінальна оцінка залишалась чесною.

## 6. Результати

**Порівняння моделей (validation set):**

| Модель | F1-score | ROC-AUC |
|--------|----------|---------|
| Logistic Regression (baseline) | 0.9223 | 0.9430 |
| LightGBM | 0.9184 | 0.9279 |
| LightGBM + Optuna | 0.9329 | 0.9314 |
| Neural Network (Embedding) | 0.9184 | 0.9033 |
| **DistilBERT** | **0.9474** | **0.9568** |

**Фінальна оцінка обраної моделі (test set, одноразово):**

| Модель | F1-score | ROC-AUC |
|--------|----------|---------|
| **DistilBERT** | **0.9422** | **0.9526** |

**Як читати ці цифри нетехнічному читачу:** з кожних 100 відгуків модель правильно визначає рекомендацію клієнта приблизно у 94 випадках. Помилки моделі несиметричні - вона трохи гірше розпізнає саме незадоволених клієнтів (клас у меншості), ніж задоволених - це видно з confusion matrix у ноутбуці й розібрано в розділі "Обмеження" нижче.

## 7. Висновки

### Технічна перспектива

**Найкраща модель - DistilBERT**, з відривом десь 1-2 п.п. по F1 і ROC-AUC від найближчих конкурентів на validation, підтверджено на test. На відміну від TF-IDF та Embedding-моделі з усередненням векторів, DistilBERT розуміє контекст і порядок слів у реченні - критично важливо для відгуків із запереченнями та нюансами ("не сподобалось", "трохи розчарував").

Цікавий проміжний інсайт: простий baseline (Logistic Regression) виявився дуже конкурентним і обійшов навіть LightGBM/Neural Network по ROC-AUC - показує, що для текстових задач складна архітектура не завжди автоматично краща без урахування контексту.

**Аналіз помилок** показав системну закономірність: модель помиляється переважно на **амбівалентних відгуках**, де похвала і критика присутні одночасно (наприклад, клієнт хвалить дизайн, але не рекомендує через розмір чи якість тканини — або навпаки, критикує деталь, але все одно рекомендує). Модель орієнтується на загальний емоційний тон окремих фраз, а не завжди коректно визначає, яка частина відгуку є вирішальною для фінального рішення клієнта.

### Бізнес-перспектива

**Що це означає для бізнесу:** модель вже достатньо точна, щоб використовувати її як фільтр першого рівня - автоматично сортувати вхідний потік відгуків за ймовірністю незадоволення, а не як повну заміну людського рев'ю. Особливо ефективна для очевидних випадків (сильно позитивні чи сильно негативні відгуки); межові/змішані відгуки варто продовжувати направляти на ручний перегляд.

**Практичне застосування:**
- автоматичне пріоритезування черги відгуків для команди підтримки/call-center
- ранній тригер на повернення/обмін/компенсацію для явно незадоволених клієнтів
- агрегований дашборд "частка рекомендацій" по категоріях товару для комерції

**Обмеження:**
- модель гірше справляється зі змішаними за тональністю відгуками - не варто повністю автоматизувати рішення без людини в контурі для межових випадків
- навчена на одному домені (жіночий одяг, англійська мова) - перенесення на інші категорії товарів чи мови вимагає додаткового донавчання й перевірки
- `max_length` токенізації обмежено 100 токенами - дуже довгі відгуки обрізаються, важливий контекст ближче до кінця тексту може губитися

**Напрямки для подальшого розвитку:**
- збільшити `max_length` токенізації з 100 до 200
- спробувати RoBERTa для потенційно кращого розуміння довгого контексту
- об'єднати передбачення DistilBERT з табличними ознаками в ансамбль
- (бізнес-напрямок) протестувати модель на живому потоці відгуків і виміряти реальний вплив на швидкість реакції підтримки

## 8. Як запустити проєкт

### Встановлення

```bash
git clone [https://github.com/NataMaru/review-based-recommendations]
cd review-based-recommendations
pip install -r requirements.txt
```

### Дані

Завантажте датасет з [Kaggle](https://www.kaggle.com/datasets/nicapotato/womens-ecommerce-clothing-reviews) і покладіть файл `Womens Clothing E-Commerce Reviews.csv` у корінь репозиторію (поруч із `review_based_recommendations.ipynb`).

### Запуск

Проєкт оформлено як єдиний Jupyter Notebook `review_based_recommendations.ipynb`, що містить усі етапи послідовно - від EDA до фінального аналізу помилок.

```bash
jupyter notebook review_based_recommendations.ipynb
```

**Примітка:** для навчання DistilBERT рекомендовано GPU (наприклад, безкоштовний T4 у Google Colab) - на CPU навчання значно довше.
